# 《一勺到底 / Spoon to the Core》

原创 2D 横屏混合休闲挖掘游戏的完整制作资料库。

- 引擎：Cocos Creator 3.8.8 + TypeScript
- 首发平台：CrazyGames Web、Android
- 后续平台：微信小游戏
- 单局时长：3—5 分钟
- 变现方式：激励广告为主，轻内购为辅

---

## 源码位置（阶段 0）

正式工程在 [`game/`](game/)。用 **Cocos Creator 3.8.8** 打开该目录，场景为 `assets/scenes/boot.scene`。

```text
game/
  assets/scripts/     domain / data / save / platform / ui / bootstrap
  assets/config/      4 方块、5 宝物、2 工具、1 地层
  assets/scenes/      boot.scene
  tests/              Node 单测，不依赖编辑器
```

不依赖 Creator 时，在仓库根或 `game/` 下（Node 22+）：

```text
cd game
npx tsx --test tests/*.test.ts
```

Grok Build 里的网页预览只是同一套 domain 的宿主，**不是**正式运行层。正式版本仍是这个 Cocos 工程。

阶段 0 已完成：标题页、状态机、seed 随机数、配置校验、`schemaVersion: 1` 存档。Creator 实机 Web 包仍需在本地编辑器里打一次。

## 给 AI 开发助手的第一条指令

如果你是被要求“照这个仓库做”的 AI，请严格按下面顺序执行，不要跳步。

### 第一步：只做阅读和确认，不要写代码

先完整读取：

1. [`01_GDD.md`](01_GDD.md) — 玩法、数值、界面、内容、商业化
2. [`02_BUILD_STAGES.md`](02_BUILD_STAGES.md) — 分阶段开发提示词与验收标准

读完后，只回答三件事：

1. 用你自己的话复述核心循环、MVP 范围，以及明确不做的内容
2. 指出「阶段 0：建立项目骨架」是否存在技术冲突或缺失
3. 列出你准备在阶段 0 新增的文件清单

**在使用者明确说「进入阶段 0」之前，不要生成工程代码。**

### 第二步：一次只做一个阶段

`02_BUILD_STAGES.md` 里有阶段 0 到阶段 9 的完整提示词。规则是：

- 一次只执行一个阶段
- 每个阶段结束后必须给出：完成内容、改动文件、运行方式、测试结果、人工验收步骤、已知风险
- 没有实际测试和 Web 构建证据，不得声称「已通过」
- 不得为了让测试通过而删除功能或绕过断言
- 不得擅自增加联网、账号、抽卡、排行榜、多人玩法

### 第三步：美术和音频不由你生成

需要制作正式资产时，再看 [`03_ART_AUDIO.md`](03_ART_AUDIO.md)。

你的职责只有两个：

1. 输出缺失资产清单（资源 ID、用途、尺寸、格式、触发位置）
2. 把使用者确认过的资产接入工程

不要自己生成、替换或凭空假设美术与音频文件。

## 硬性约束

1. 玩法规则与 Cocos 节点分离，`domain` 目录尽量使用纯函数
2. 方块、宝物、工具、地层、任务、广告奖励全部走配置，禁止散落硬编码
3. 每局使用 seed 随机数，地图可复现
4. 平台能力必须通过 `PlatformAdapter` 调用，业务代码不得直接调用 `wx`、CrazyGames 或 Android API
5. 存档必须带 `schemaVersion` 和迁移函数
6. 灰盒阶段只用程序化色块与文字占位，不引入来源不明的素材
7. CrazyGames Basic Launch 阶段完全隐藏广告入口，不得留下点击无效果的广告按钮
